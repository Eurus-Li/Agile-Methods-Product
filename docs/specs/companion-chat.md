# Spec: Companion Chat

**Status:** Implemented in the web demo (needs a Groq API key on the local dev server) · **iOS modules:** `Features/Home`

**English name:** Companion Chat (首頁寵物聊天)

## Goal

Let the user type to their pet on Home and get a short, warm reply generated by the open-weight **gpt-oss** model, so the companion feels present beyond preset replies.

## User story

As a user, I want to tell my companion how I'm doing in my own words and get a caring reply, so that I feel listened to.

## Core interaction flow

1. Home shows "💬 Talk to {petName}". It opens a chat dialog with a short notice: replies come from gpt-oss through Groq, messages are not saved, and the pet is a companion, not a therapist.
2. The pet greets the user with their call-me preference. The user types up to 500 characters; Enter sends, Shift+Enter adds a new line.
3. While waiting, a "{petName} is thinking…" bubble appears and Send is disabled. The reply replaces it.
4. Closing and reopening the dialog in the same tab keeps the conversation; reloading, or Reset demo data, clears it.

## Architecture

```
Browser (app.js)  --POST /api/chat {history, context}-->  scripts/serve.js  --Bearer GROQ_API_KEY-->  Groq Chat Completions
```

- The browser never sees the key. `serve.js` reads `GROQ_API_KEY` (and optional `GROQ_MODEL`) from the environment or the git-ignored `web/.env.local`.
- Default model `openai/gpt-oss-20b`, `reasoning_effort: "low"`, 30s timeout.
- The system prompt is built on the server from sanitized context only: pet name, how to address the user, today's mood (if checked in) and goal names. Client-sent `system` turns are dropped; only the latest 12 user/assistant turns are forwarded.
- `/api/chat` accepts only same-origin JSON (other origins get 403, non-JSON 415), bodies up to 16 KB, and the server only listens on 127.0.0.1.
- Shared pure logic: `web/src/js/companion-chat.js` (`RongrongChat`).

## Safety

- Messages mentioning suicide or self-harm (English and Chinese patterns) never reach the model, on either the client or the server. They get a fixed reply pointing to local emergency services, Taiwan 1925 and US 988, and to someone the user trusts. Earlier crisis messages and their replies are also removed from the history of later requests.
- The prompt keeps replies to 1–3 short sentences and forbids diagnosis, medical/legal/medication advice and claiming to be human.
- Replies are rendered with `textContent` and capped at 800 characters.

## Edge cases

- No key → server returns 503 `missing_key`; the pet answers with a gentle fallback and a toast explains how to enable chat.
- Groq error, timeout or empty reply → fallback reply; details are only logged in the dev server terminal.
- Chat does not add bond and does not change mood, journal or activity data.

## Acceptance criteria

- [ ] With a key, a message gets a gpt-oss reply in the pet's voice using the chosen call-me preference.
- [ ] Without a key, the app still works and shows the fallback reply and setup hint.
- [ ] Crisis messages show the fixed help reply and make no Groq call.
- [ ] Conversation is never written to `localStorage`.
- [ ] Cross-origin or non-JSON POSTs to `/api/chat` are rejected.
- [ ] 320px width has no horizontal overflow; input and Send are keyboard reachable.
