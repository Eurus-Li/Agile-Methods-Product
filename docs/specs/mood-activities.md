# Spec: 心情活动推荐（Release 1.1）

**状态:** 已在 Web demo 验证 · **对应 iOS 模块:** `Features/Reply`（工程尚未建立）

## 目标与用户故事

用户记录心情后，可以从三个轻量活动中挑选一个，查看预计时间与具体步骤，决定此刻想做什么。

## 核心交互流程

1. Reply 在心情回应后展示恰好 3 张活动卡，按 Calm / Happy / Tired / Sad / Tense 使用固定本地推荐顺序。
2. 每张卡显示名称、预计时间、简介及「View details」按钮；打开详情不代表已选择。
3. 详情显示名称、时间、介绍、步骤与「Select activity」。确认后回到卡片列表，以文字和 aria 状态显示 Selected。
4. 每个日期只保存一项选择；选择其他推荐活动时替换。同心情重复打卡保留选择；改心情时清空选择并更新推荐。
5. Home 的活动入口可再次查看当天推荐；未打卡时提示先选心情。Journal 的历史日期可查看该日活动推荐及选择。
6. 关闭详情或按 Escape 不改变选择；刷新后恢复选择。所有活动免费，不依赖 Plus。
7. 确认选择后，在当前弹窗显示 Rongrong 的开心反馈：沿用当前皮肤与配饰，小狗轻跳、左右摇摆，爱心上浮。动画短暂播放后停止，用户可随时关闭或按「Back to activities」回到卡片；不自动跳页。文字确认与动画同时出现，系统开启减弱动态效果时仅显示静态小狗与确认文字。浏览详情、取消或刷新不触发庆祝，不改变心情或 Bond。

## 数据与边界

`entries[dateKey].activityId: string | null`，旧数据默认 null。未知 ID 或不属于当前心情推荐的 ID 读取时清空。无效心情不生成推荐、不允许选择。推荐逻辑与 DOM 分离，不发送网络请求。

iOS 建立 SwiftData 模型时增加可空 activityId，旧记录迁移为 nil，复用同一目录 ID 与映射规则；当前不创建完整 iOS 工程。

活动不涉及计时、完成打卡、额外 Bond 奖励或治疗承诺；这些不属于本次四项故事范围。

## 验收标准

- [x] 五种心情各返回三个不重复、有完整详情的活动。
- [x] 查看/取消详情不改变状态；选定/替换有文字反馈并保留至刷新后。
- [x] 同心情重打卡保留选择，改心情清空，不影响 note/saved/hugged 或重复增加 Bond。
- [x] 旧数据、无效 ID、缺失心情安全处理；历史日期与今天互不覆盖。
- [x] 手机布局可滚动、键盘可操作、弹窗关闭后焦点恢复。
